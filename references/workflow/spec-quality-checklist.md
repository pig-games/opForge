# Spec Quality Checklist

A specification is ready for planning only if it has:

- problem statement
- goals
- non-goals
- assumptions or invariants
- boundary behavior where relevant
- testable acceptance criteria
- validation expectations
- explicit unresolved questions

Common failure modes:

- goals without non-goals
- aspirations instead of acceptance criteria
- hidden design decisions left implicit
- plan content mixed into the spec
- implementation language without behavioral contract
