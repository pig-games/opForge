# opForge Review Reporting

Lead with actionable findings, including location, concrete trigger, consequence
and a supported correction direction. Distinguish defects from optional design
suggestions. State relevant testing gaps and uncertainty. Preserve finding IDs
when following an existing review; do not allocate a global ID for ordinary
comments. Adjudicate multiple reviewers by evidence rather than vote count.
Do not require every open design question to be settled before reporting a defect.
Use conversation or PR comments unless a file has an active purpose. No independent
approval, structured receipt or prescribed template is required.
