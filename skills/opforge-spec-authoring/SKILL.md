# opForge Spec Authoring

Describe the problem, intended behavior, scope exclusions, relevant invariants,
boundary cases and testable acceptance criteria. Separate decisions from open
questions. Do not force an implementation plan into a behavior contract. Choose
a format proportional to the task; no template, checkbox schema or sidecar is
required. Keep a specification only while it is active or maintained as a current
reference; remove superseded drafts after preserving enduring information.
